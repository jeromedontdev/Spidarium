Regenerate climb art with nano banana and fix the importer quantizer

The six large climb structures now use generated art instead of the
procedural fallback, and the climb is a slope that runs up the screen
rather than a radial lift from the centre.

Two importer faults shipped in the previous round. Keying sets alpha but
leaves each transparent pixel's RGB in place, so median-cutting the
cropped image spent palette entries on invisible background: the
white-background root burned 8 of its 12 entries on near-white and had
only 4 visible tones. The palette is now built from the opaque pixels
alone and every pixel maps to its nearest entry, so all six use the full
12 tones. Four of the six also still carried the generator's drawn
transparency checkerboard as opaque pixels; all six are re-imported from
the original JPEGs.

The stale-pack failure was not a code defect: asset_build.py compares the
packed QOI against the source PNG and the pack is produced by the build,
so editing an asset without rebuilding always reports a mismatch.

Verified: asset_build.py passes all checks, build exit 0 with zero main
warnings, flash exit 0 with Hash of data verified, device screenshot
shows the generated art on the panel, browser suite 256/256, native suite
49/3 (documented baseline), soak PASS with 0 faults, render 500 and
scanloop 5 both largest_drift=0, largest=63488.
